# Prompt Library

## Context Management

Prompts for preserving or transferring conversation state.

### Compact — preserve decisions & changes

`/compact` — Preserve all decisions, changes, and additions made this session. Prioritize: (1) explicit decisions/confirmations, (2) file changes and additions, (3) rationale behind them. Compress general discussion/exploration first.

### Handoff summary — resume in new chat

Act as an expert technical archivist. Generate a comprehensive handoff summary of our entire conversation so far. Format it so I can paste it directly into a brand-new chat to resume work seamlessly without losing context. Include: (1) Core project goals and overall objective, (2) Key decisions made and constraints established, (3) Current technical stack, file structures, or core components discussed, (4) Exact state of what we just finished, and (5) The immediate next steps or open tasks we need to tackle. Be dense with technical specifics, code snippets or logic paths if applicable, but concise enough to fit efficiently into a new context window.

## UI/UX Animation & Transitions

Prompts for auditing and upgrading motion design in a frontend codebase.

### Motion audit & upgrade — principles + reusable patterns

Act as a senior motion/interaction designer doing a paid audit of this codebase's animations and transitions, then fixing what you find. Start with inventory and restraint, not output: list every place motion currently exists (CSS transitions/keyframes, animation libraries like Framer Motion, custom hooks that gate animation lifecycle, autoplay/carousel logic) and every place it's conspicuously absent on interactive elements (buttons, cards, modals, menus, toggles, form validation, loading/empty states) — but don't propose motion just because a gap exists; only add it where it serves the interaction, since scattered, unmotivated animation is exactly what makes an interface read as AI-generated. One deliberate, orchestrated motion moment beats several small competing ones. Score everything that exists (and everything you're about to add) against this checklist, citing file:line for every violation:
- **Timing & easing** (Disney's 12 principles, adapted for web): user-initiated feedback completes within 200-300ms; entrances use ease-out, exits use ease-in; similar elements share identical timing values; springs (not eased tweens) for any overshoot-and-settle motion; stagger delays ≤50ms/item; only one focal point animates prominently at a time; modal/dialog backgrounds dim to direct focus.
- **Hard constraints** (non-negotiable, flag any violation as a bug not a style note): animate only compositor-friendly properties — `transform`, `opacity` (never `width`, `height`, `top`, `left`, `margin`, `padding`, and go easy on animating `background`/`color` outside small local UI); never `transition: all`; `will-change` only ever on `transform`/`opacity`/`filter`, and only while an animation is actually active, never left on at rest; looping/ambient animation pauses when scrolled off-screen; `prefers-reduced-motion` gets an intentional reduced alternative (state still changes, it just doesn't animate) rather than a blanket kill.
- **Interface-polish details**: interruptible CSS-transition state changes for anything interactive (reserve one-shot keyframes for staged sequences that run once); split enter animations into staggered chunks rather than animating one container; exits subtler than enters (small fixed offset, not a full reverse of the entrance); icon-only buttons get `aria-label`; scale-on-press at exactly `0.96` (never below `0.95` — it starts to feel exaggerated); contextual icon cross-fades instead of hard visibility toggles; `AnimatePresence` (or equivalent) uses `initial={false}` so nothing plays an unwanted entrance on first page load.
- **Visual QA pass**: separately from the checklist above, look for motion that's simply janky or inconsistent in practice — animations that feel slow, stutter, fight with each other, or make near-identical interactions (two similar buttons, two similar cards) behave with different timing or easing for no reason.

Then, for gaps where a well-tested, accessible pattern already exists rather than a bespoke one — dropdowns, modals, panel reveals, notification badges, success confirmations, input-shake on validation error, page transitions, icon swaps, number pop-ins — pull the matching transition from transitions.dev (https://transitions.dev, `npx transitions-pro`, or its agent skill) instead of hand-rolling it; its `t-*` snippets already ship with `@media (prefers-reduced-motion: reduce)` guards and semantic custom properties, so adapt them to this project's existing motion tokens/hooks rather than importing a second animation system. Respect whatever animation lifecycle/gating hooks and design tokens the project already has (e.g. an intro-motion hook that plays once, stops on interaction, and pauses off-screen) — extend that pattern to new motion instead of introducing a competing one. Deliver: (1) the audit table of violations grouped by checklist category, (2) a prioritized list of missing-motion opportunities with the exact transitions.dev pattern or hand-written values to use for each (and an explicit "skip" note for any gap that's better left unanimated), (3) the diffs applied, as before/after tables — nothing that changes behavior or copy outside of motion/timing/easing.
